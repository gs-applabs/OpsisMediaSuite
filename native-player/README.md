# Experimental LibVLC native playback host
Separate WinForms window, local files only, process isolation (not a security sandbox). Explicit user action only; not an automatic fallback or embedded adapter. Own transport, audio/subtitle tracks, external subtitles, delay and volume. Source uses pinned LibVLCSharp 3.10.2 / VideoLAN.LibVLC.Windows 3.0.24 (non-GPL package); .NET 10 Windows x64. No global codec settings changed. CI compiles and runs a real generated MKV with two audio tracks and SRT, using dummy video/audio outputs. This verifies playback clock and track selection, not rendered pixels, audio quality or GPU. Source-only until CI and redistribution/license review. For development run dotnet publish native-player/Opsis.NativePlayer.csproj -c Release -r win-x64 --self-contained true -o native-player/publish. Main process discovers that exact executable in dev, or resources/native-player/Opsis.NativePlayer.exe in packaged build; no native binary auto-download. Do not copy unverified binaries into this location. Native host does not share Chromium DSP or resume yet. DirectShow/Media Foundation adapters pending. VideoLAN licensing review and notices required before distributing native artifacts.

## Experimental DirectShow
Explicit `--directshow` path builds LAV source -> LAV audio/video decoders -> explicitly chosen Windows renderers using ConnectDirect, not intelligent graph building. Only machine x64 registrations under Program Files, no per-user override; explicit per-launch approval shows paths and SHA256, direct class factory loading, local DLL directory and System32 search only. Hashes identify the files, do not prove publisher authenticity. Adjacent dependencies are not individually pinned; ACL/authenticode verification and license review still required before shipping. Currently expects both audio and video, no subtitle graph, no automatic fallback. `--directshow-selftest` uses built-in Windows WAV graph with null renderer; this does not verify installed LAV or actual visual output. Separate process, not a sandbox.

Codec-pack CI uses a pinned Chocolatey K-Lite Mega 20.1.0 on a disposable Windows VM only. Test build defines CODEC_CI_TEST; this build is not distributable and is never published. The test explicitly connects installed LAV filters to null renderers and records graph progress plus hashes; no interactive consent is skipped in normal binaries. No claims of actual screen/audio quality or verified publisher identity from this test.

K-Lite may install x64 modules under Program Files (x86). Both standard Program Files roots are allowed; PE x64 remains independently mandatory. Product label detection is advisory, actual machine CLSID registration is required for codec CI.

## Media Foundation (decode diagnostic)
Source Reader independently negotiates PCM and NV12 and reads actual decoded samples from local WAV and H.264/AAC MP4 fixtures. No video renderer, audio endpoint or app playback adapter yet. Windows selects its own transforms; this does not verify active decoder identity or third-party transform trust. Parent CI imposes process timeout. This diagnostic is not advertised as a production player.

Native handoff now accepts bounded resume milliseconds, reports JSON ready/position/closed/error on stdout, and main process waits for readiness (120s cap, including consent). Separate window remains; opt-in LibVLC fallback does not imply embedded playback. DirectShow readiness is graph run success; visual certification pending.

Selected corrected text subtitle is passed to LibVLC as a temporary canonical SRT (main owns path; bounded). Host reports whether AddSlave accepts it; dedicated selftest validates external track selection. Native subtitle timing/visual verification still pending; no DirectShow handoff.

LibVLC central transport uses a bounded stdin JSON command and stdout ack, fixed verbs only, one outstanding command, session check. Native status includes play/mute/volume. DirectShow does not yet support this bridge. Native CLI control test exercises the same parser/actions with dummy output; interactive WinForms IPC remains unverified.

## Integrated test candidate
The dedicated native-candidate workflow builds a private unsigned directory candidate with the native host in resources/native-player and tests the packaged app, workers and real native pipe. Only evidence logs and inventories are uploaded, not the binaries. The default distribution configuration is unchanged pending licensing review and release gates.

DirectShow now has fixed command pipe for toggle/play/pause/seek/rate (graph HRESULT checked and actual running state reported); WAV graph pipe test validates seek and invalid commands. Installed-LAV graph still requires explicit consent. Native visual and hardware certification, volume/mute and subtitle graph remain outstanding.
